CAPACIDADES

Informação útil, sem transformar ausência em zero.

O projeto lê interfaces do kernel e mantém explícitos os estados de cada observação. A disponibilidade e o significado dos dados dependem do hardware, dos drivers e do ambiente.

↗

Uso da CPU

Calcula utilização agregada comparando amostras de /proc/stat. A primeira amostra estabelece o baseline.

▦

Topologia

Consulta modelo, flags e contagem de processadores lógicos e núcleos físicos identificáveis.

◉

Temperatura e frequência

Lê interfaces expostas pelo kernel. Sensores ausentes, erros e leituras implausíveis não devem ser interpretados como valores reais.

API de diagnóstico

Relatório C com status, erro, mensagem e origem disponível por métrica para consumidores da biblioteca.

CONFIANÇA E AUDITORIA

Origem conhecida. Limites documentados.

O CPU Reader reporta observações fornecidas pelo sistema operacional. Não verifica de forma criptográfica a integridade do host nem a calibração física dos sensores.

✓

Status por métrica

Distinga dado válido, baseline, indisponibilidade e erro em vez de presumir que toda leitura é válida.

⌁

Ambientes limitados

VMs e containers podem ocultar interfaces ou expor uma visão parcial do hardware do host.

◇

Validação reproduzível

Use SHA do commit, logs do workflow e arquitetura do runner para contextualizar resultados de CI.

!

Proteção de dados

Relatórios podem revelar modelo, flags, topologia e caminhos de sensores. Redija informações do host antes de compartilhar.

PERGUNTAS FREQUENTES

Respostas para começar.

Se a sua dúvida não estiver aqui, consulte o manual ou abra uma issue sem incluir dados sensíveis da máquina.

O CPU Reader funciona em Windows ou macOS?

Não. O projeto depende de interfaces do Linux, principalmente /proc e /sys.

Por que a temperatura ou frequência não aparece?

O kernel precisa expor uma interface compatível e legível. A cobertura automática de temperatura é limitada às zonas térmicas suportadas pela implementação; a ausência de leitura não significa temperatura segura.

Preciso executar como root?

Não para as operações normais. Execute com permissões elevadas somente quando um caso específico de diagnóstico justificar isso e compreenda o risco adicional.

Por que a primeira amostra de uso não representa uma porcentagem?

O uso é calculado a partir da diferença entre amostras sucessivas de /proc/stat. A primeira leitura estabelece o baseline; colete outra depois de um intervalo.

O pacote .deb funciona em qualquer distribuição Linux?

Não. Ele é destinado a Debian e distribuições derivadas compatíveis com as dependências declaradas, e é gerado para a arquitetura local. Consulte a matriz de suporte antes de distribuir.

O projeto envia telemetria do meu computador?

O site é estático e não possui formulário de envio de dados. A biblioteca lê interfaces locais do Linux; ainda assim, os relatórios que você copiar para issues podem conter detalhes identificáveis do host. Revise-os antes de publicar.

Os relatórios provam que o hardware é íntegro?

Não. Eles são observações fornecidas pelo kernel e pelos drivers. Não constituem atestação de firmware, kernel ou hardware e não substituem ferramentas especializadas de auditoria.

Como reporto um bug ou contribuo?

Leia CONTRIBUTING.md, procure uma issue existente e abra um relato reproduzível. Para questões sensíveis, siga a política de segurança.
